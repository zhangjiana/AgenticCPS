# CPS 返利管理后台：MVP 业务范围与维护说明

## 目标

将 AgenticCPS 的原管理后台以 **CPS 专用模式** 提供给返利助手运营人员，集中完成商品转链、订单归因、返利/资金对账、提现审核、联盟平台配置。此阶段是 **前端工作台和菜单隔离**，保留共享后端基础设施和原有全功能后台，不删除数据表或 Java 模块。

## CPS 业务导航

当前授权菜单仍由 `/admin-api` 的登录用户信息提供，前端在显示前按业务白名单裁剪：

| 分组 | 显示的页面（需已由后端授权） | 对应后端菜单根路径 |
| --- | --- | --- |
| 商品与推广 | 返利转链工具、商品查询、转链记录 | `/cps-ops` |
| 订单与资金 | 订单管理、返利记录、提现审核、冻结规则、资金账本、风控规则 | `/cps-settlement` |
| 联盟配置 | 平台接入配置（包括供应商、推广位、返利规则） | `/cps-config` |
| 会员管理 | 会员列表（仅在授权菜单中存在时展示） | `/member` |

暂不纳入：CPX 任务和资讯、AI 模型和 Token、普通商城商品/交易、BPM、CRM、低代码、通用系统设置。它们在全功能模式与原代码中仍可用。CPS 平台配置中心已统一处理推广位、供应商及返利规则，不重复展示旧页面。

## 启用与恢复

`frontend/admin-vue3/.env` 默认设置：

```dotenv
VITE_APP_TITLE=返利助手管理后台
VITE_ADMIN_SCOPE=cps
```

本地启动（保持现有服务、接口及权限配置）：

```bash
cd frontend/admin-vue3
pnpm install
pnpm dev
```

生产构建使用现有 `pnpm build:prod`；修改 `VITE_ADMIN_SCOPE=full` 后重新构建，即可恢复完整后台菜单与原首页。

注：该开关属于 **编译环境配置**，不是运行时切换，不应在浏览器直接暴露一个能绕过权限的切换按钮。

## 文件布局

- `src/utils/cpsAdminMenu.ts`：基于后端已授权菜单，过滤并重新命名 CPS 菜单；不会增加权限
- `src/store/modules/permission.ts`：在原动态路由生成链路中插入 CPS 作用域过滤
- `src/router/modules/remaining.ts`：CPS 专用模式使用新的工作台首页，full 模式仍使用原首页
- `src/views/cps/workbench/index.vue`：新的运营首页，真实 API 指标、权限感知快捷入口、资金提醒
- `script/test/test_cps_admin_menu.mjs`：菜单作用域回归测试

## 约束与风险

1. **不是后端授权**：前端菜单裁剪只能简化导航；服务端仍须按角色、租户和会员上下文校验所有接口。不能仅靠隐藏页面保护订单或资金。
2. **不伪造数字**：运营首页指标从 `CpsStatisticsApi.getDashboard()` 获取，没有权限或接口不可用则显示 `—`，并提示错误。
3. **后端菜单仍是来源**：白名单项目如果在该用户已授权菜单中不存在，不能由此过滤逻辑创造入口。
4. **提现仍受安全规则保护**：CPS 工作台不修改审核权限、资产账本、解冻规则或支付通道。
5. **CPS 页面与依赖尚未物理拆包**：本阶段没有删除 Java 的 system/member/pay/infra 模块，因为登录、RBAC、会员及提现会依赖它们。
6. **已有统计 API 可能无权限**：原数据库曾将统计独立菜单标记隐藏，页面在缺少统计权限时只显示 `—`，不影响其他业务。
7. **刷新权限缓存**：新角色菜单授权后，请重新登录以更新 `ROLE_ROUTERS` 缓存。

## 验证步骤

```bash
node --experimental-strip-types script/test/test_cps_admin_menu.mjs
cd frontend/admin-vue3
pnpm ts:check
pnpm build:prod
```

人工验收：
- CPS 模式：菜单只包含授权过的返利功能、首页不显示广告，不出现 CPX、商城和 AI 导航
- 未授权账号：不会被前端补出任何 CPS 页面；后台 API 仍应拒绝非法访问
- 登录后的工作台快捷入口仅导航到后端授权的页面；刷新和直接访问路径行为一致
- full 模式：仍可访问旧首页和完整动态菜单，保持现有角色控制
- 提现和结算：仅导航和展示，不改变资金状态或自动发起转账
